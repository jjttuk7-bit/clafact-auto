# 직접값 381건 대상값 원문 연결 설계

## 목적

숫자 역할 분류 결과를 보고서에만 남기지 않고 실제 Registry와 통합 파이프라인 입력으로 연결한다. 자동 처리되는 Claim에는 원문의 정확한 대상 숫자 표현과 위치가 반드시 있어야 한다.

## 선택한 방식

1. 역할 분류 CSV를 Claim 번호로 읽는다.
2. `TARGET_SELECTED`는 자동 대상 표현이 원문에 정확히 한 번 존재하고 역할 목록의 시작·끝 위치와 일치할 때만 `SOURCE_GROUNDED`로 확정한다.
3. 확정 결과를 `slot_enrichment`에 병합할 수 있는 보강 JSONL로 저장한다.
4. 통합 파이프라인은 보강된 `target_numeric_expression`을 `recover_validated_claim`의 원문 검증 범위로 사용한다.
5. 연결되지 않은 Claim은 공식조회 실패로 표시하지 않고 다음 공식조회 전 사유로 중단한다.
   - `TARGET_CONTEXT_ROLE_CONFLICT`: 기간·연령·순위·환산값이 저장 기사값임
   - `TARGET_NOT_FOUND_IN_SOURCE`: 저장 기사값·단위가 원문 검증값과 맞지 않음
   - `TARGET_AMBIGUOUS_IN_SOURCE`: 같은 값이 반복되어 하나를 고를 수 없음

## 제외한 방식

- CSV에 표현만 추가: 대시보드·배치가 소비하지 못하므로 제외한다.
- 저장 기사값·단위를 즉시 수정: 다음 단계의 단위·부호 검증 전에는 오수정 위험이 있어 제외한다.
- 연결되지 않은 값을 임의로 선택: 원문 근거 계약을 위반하므로 제외한다.

## 산출물

- 381건 원문 연결 결과 CSV
- 파이프라인 보강 JSONL
- 검증 JSON
- 성공·실패·수정 이력 CSV
- 쉬운 결과 보고서와 체크리스트 상태 JSON

## 완료 조건

- 381건 결과와 고유 Claim 381건
- `SOURCE_GROUNDED` 모든 행에 표현·mention ID·시작·끝 위치 존재
- 표현과 원문 부분 문자열 불일치 0건
- 파이프라인 보강자료 381건, 연결 365건과 미연결 16건 사유 누락 0건
- 통합 파이프라인이 연결 표현을 사용하며, 미연결 보강 Claim은 공식 API 호출 전에 정확한 재구조화 사유로 중단
