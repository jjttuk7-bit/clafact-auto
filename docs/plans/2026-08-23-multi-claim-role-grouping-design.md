# 여러 수치가 포함된 Claim 분리 설계

## 목적

문장 안의 모든 숫자를 별도 Claim으로 나누지 않고, 실제로 서로 독립된 검증 주장만 분리한다.
첫 적용 범위는 고용 분야 대표 20건이며 전체 1,542건은 실행하지 않는다.

## 현재 문제

현재 `targeted_claim_splitter`는 단위가 붙은 숫자를 각각 분리 대상으로 삼는다.
따라서 다음처럼 하나의 비교 주장에 필요한 숫자들도 여러 Claim으로 잘못 나뉠 수 있다.

> 고용률은 60%로 전년 58%보다 2%포인트 올랐다.

이 문장의 60%, 58%, 2%포인트는 독립된 세 주장이 아니라 현재값·과거값·증감값으로 구성된 하나의 검증 주장이다.
반대로 서로 다른 지표가 함께 서술된 문장은 실제로 여러 자식 Claim으로 분리해야 한다.

## 선택한 해결 방식

숫자를 찾는 단계와 Claim을 묶는 단계를 분리한다.

1. 원문에서 모든 수치 표현을 결정적으로 찾는다.
2. Structured Output이 각 수치의 역할과 소속 Claim 묶음을 제안한다.
3. Python 검증기가 원문 근거, 수치 누락, 중복 사용, 단위 및 묶음 규칙을 검사한다.
4. 검증을 통과한 묶음만 자식 Claim으로 생성한다.
5. 각 자식 Claim을 12개 항목으로 구조화하고 기존 Admission 경로에 다시 넣는다.
6. 애매하거나 규칙에 맞지 않는 결과는 자동 통과시키지 않고 검토 대상으로 남긴다.

## 수치 역할

- `MAIN_VALUE`: 기사에서 직접 주장한 중심 수치
- `REFERENCE_VALUE`: 과거·전기·비교 대상 수치
- `CHANGE_VALUE`: 증감량 또는 증감률
- `EQUIVALENT_VALUE`: 환산값이나 괄호 안의 같은 값
- `CONTEXT_VALUE`: 순위·기준선·설명용 숫자
- `INDEPENDENT_VALUE`: 다른 지표에 속하는 별도 중심 수치

역할명은 내부 코드에서만 사용한다. CSV에는 이해하기 쉬운 한글 설명을 함께 기록한다.

## 묶음 규칙

- 현재값, 비교값, 증감값이 같은 지표·기간 비교를 설명하면 하나의 Claim으로 묶는다.
- 괄호 안 환산값이나 다른 단위로 표현한 같은 값은 별도 Claim을 만들지 않는다.
- 순위, 기준연도, 표본 수처럼 지표의 검증 대상이 아닌 숫자는 별도 Claim을 만들지 않는다.
- 지표나 대상이 실제로 다르면 각각의 자식 Claim으로 분리한다.
- 하나의 수치가 서로 양립할 수 없는 두 Claim에 중복 배정되면 실패 처리한다.
- 원문에서 찾지 못한 수치를 새로 만들면 실패 처리한다.
- 수치 역할이나 소속을 확정할 수 없으면 검토 대상으로 남긴다.

## 기존 파이프라인 연결

```text
원문
→ 수치 표현 찾기
→ 역할 및 Claim 묶음 제안
→ Python 안전 검사
→ 자식 Claim 생성
→ 12개 항목 구조화
→ 재입장 판정
→ 통과한 자식만 공식통계 검색 단계로 전달
```

이번 묶음의 실행 범위는 Claim 분리부터 재입장 판정까지다. 공식통계 조회는 분리 정확도가 확정된 자식 Claim만 후속 묶음에서 수행한다.

## 20건 기준 자료

고용 분야에서 다음 패턴이 포함되도록 20건을 고정한다.

- 현재값 + 과거 비교값 + 증감값
- 현재값 + 증감값
- 서로 다른 두 지표
- 괄호 안 환산값
- 순위·기준·설명용 숫자 포함
- 분리 여부가 애매하여 검토가 필요한 문장

각 행에는 사람이 확인한 기대 자식 Claim 수, 각 수치의 역할, 기대 처리 결과를 먼저 기록한다.

## CSV 기록 항목

- 기사번호, 문장번호, 부모 Claim 번호, 원문
- 발견한 수치 표현
- 사람이 정한 수치 역할과 기대 Claim 묶음
- 프로그램이 정한 수치 역할과 실제 Claim 묶음
- 기대 자식 수, 실제 자식 수
- 자식별 12개 항목과 각 항목의 상태
- 재입장 결과와 중단 사유
- 개선 전후 결과
- 코드 버전, 자료 버전, 실행시각

## 완료 기준

- 20건의 기대 자식 수와 실제 자식 수가 모두 일치한다.
- 검증할 Claim 누락이 0건이다.
- 불필요하게 생성된 Claim이 0건이다.
- 원문에 없는 수치가 자동 Claim으로 통과한 사례가 0건이다.
- 애매한 사례가 자동 통과하지 않고 정확한 사유로 검토 대상이 된다.
- 모든 자식 Claim의 12개 항목과 재입장 결과가 CSV에 기록된다.
- 기존 안전장치 및 전체 자동 테스트에 회귀가 없다.

## 확대 순서

20건을 통과한 뒤에만 50건, 100건, 해당 유형 전체 순으로 확대한다.
개발 중에는 전체 1,542건 실행을 금지하고, 모든 주요 유형이 완료된 후 최종 확인에서 한 번만 전체 실행한다.
