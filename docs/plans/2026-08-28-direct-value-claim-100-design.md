# 직접값 Claim 구조·분류 100건 재판정 설계

## 목적

8번 직접값 230행 원장에서 Claim 구조·분류 문제로 남은 100건을 전량 재판정한다. 결과는 서로 겹치지 않는 세 갈래로 확정한다.

1. 원문 근거로 슬롯을 복구하고 직접값 검증에 유지
2. 증감량·증감률·비중·기록·순위 등 올바른 검증 유형으로 이동
3. 전망·정책 기준·민간 거래 등 공식 통계 검증 대상에서 제외

## 대상 동결

대상은 현재 `개선후사유`가 Claim 구조·분류 사유 집합에 속하는 정확히 100행이다. 기존 `사용집합`을 그대로 유지하여 규칙 발견 71건, 중간 검증 21건, 최종 미사용 8건으로 나눈다. 최종 미사용 원문은 규칙 확정 전 분석에 사용하지 않고 마지막에 한 번만 실행한다.

## 판정 순서

1. 원문 수치 목록과 수치 역할을 다시 계산한다.
2. 구조화된 기사값이 원문의 어느 수치와 연결되는지 유일하게 확인한다.
3. 연결된 수치 주변 표현으로 직접값·증감량·증감률·비중·기록·순위를 판정한다.
4. 전망·정책 기준·민간 계약이면 공식 조회 대상에서 제외한다.
5. 직접값으로 남는 Claim은 기존 공통 파이프라인의 Structured Output 복구와 공식 KOSIS 경로로 다시 투입한다.
6. 불확실한 경우 임의로 유형을 정하지 않고 직접값 복구 필요 상태로 남기되 정확한 원인과 근거를 기록한다.

## 공통화 원칙

- Claim ID나 특정 문장으로 분기하지 않는다.
- 원문 수치 역할, 계산 표현, 지표·단위·시점 슬롯을 입력으로 사용한다.
- 재분류 규칙은 Streamlit·배치·CLI가 공유하는 `unified_claim_pipeline`의 기존 사전 검증 규칙과 동일한 함수를 사용한다.
- KOSIS 공식값은 재분류 판단에 사용하지 않는다. 직접값으로 확정된 Claim만 공식 API 단계로 보낸다.

## 결과와 감사

100건마다 기존 사유, 재판정 결과, 이동 대상, 적용 규칙, 원문 근거 표현, 복구 슬롯, 공식 조회 진입 여부를 기록한다. 230행 통합 CSV에는 결과 열을 추가하고, 합계 100건 및 세 갈래 합계 일치를 자동 검사한다.

## 완료 기준

- 대상 100건이 정확히 동결되고 중복·누락이 없다.
- 100건 모두 하나의 최종 재판정 결과를 가진다.
- 발견·중간·최종 미사용 순서를 지키며 최종 미사용 8건은 한 번만 실행한다.
- 직접값 잔류, 6번 이동, 7번 이동, 기타 유형 이동, 검증 제외 건수가 산출된다.
- 대표 신규 문장이 같은 공통 규칙으로 같은 유형에 배치된다.
- 핵심 회귀 및 전체 테스트 후 원격 `main`에 반영한다.
