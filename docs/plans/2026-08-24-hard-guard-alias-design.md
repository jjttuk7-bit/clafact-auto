# 별칭·공식 항목 연결 실패 193건 해결 설계

## 목표와 범위

통합 원장에서 `세부문제유형=HARD_GUARD_ALIAS`인 193건만 대상으로 한다. 이 중 190건은 12개 슬롯상 공식 조회가 가능하지만, 전부 `NO_HARD_GUARD_CANDIDATE`에서 멈추고 공식값 조회와 판정이 0건이다. 전체 1,542건은 이 작업 중 재실행하지 않는다.

## 선택한 방식

뉴스 표현을 Claim별로 예외 처리하지 않는다. 기존 의미 표준의 별칭과 KOSIS 검색어를 사용하되, 실제 KOSIS에서 조회한 통계표·항목·차원 메타데이터가 그 표현을 확인할 때만 Claim 표현을 공식 명칭으로 정규화한다. 정규화된 Claim은 기존 Hard Guard, 좌표 확정, 공식값 조회, 계산, 판정 순서를 그대로 따른다.

이 방식은 다음 대안보다 안전하다.

- 193개 문장별 고정 매핑: 빠르지만 신규 Claim에 재사용되지 않아 금지한다.
- 의미 유사도나 LLM으로 후보를 강제 선택: 공식 구조 확인보다 앞서 후보를 확정하므로 실행 계약상 금지한다.

## 처리 흐름

1. Structured Output으로 생성된 12슬롯 Claim을 의미 표준에 연결한다.
2. Claim과 Concept 검색어로 실제 KOSIS Catalog 및 공식 메타데이터를 조회한다.
3. 공식 메타데이터에 존재하는 항목명·차원명·멤버명에 한해 뉴스 표현의 별칭을 정규화한다.
4. 정규화된 Claim으로 Hard Guard를 다시 적용한다.
5. 통과 후보만 좌표 확정과 KOSIS 공식값 조회로 전달한다.
6. Python 계산과 판정을 수행하고 공식 URL·좌표·응답 해시를 남긴다.
7. 같은 통합 엔진을 사용하는 대시보드 경계로 193건을 재실행한다.

## 실패 처리

- 공식 메타데이터에 대응 항목이 없으면 별칭을 적용하지 않는다.
- 서로 다른 공식 항목에 동시에 대응하면 강제 선택하지 않고 보류한다.
- 공식 API 요청 실패와 공식 후보 부재를 서로 다른 사유로 기록한다.
- 별칭 정규화가 Hard Guard의 단위·주기·기간·지역 조건을 우회하지 못하게 한다.

## 시험과 완료 조건

구현 전에 현재 실패를 재현하는 테스트를 작성한다. 수출액, 취업자 수, 총인구, 고용률, 물가상승률, 출생아 수의 반복 표현을 포함하고, 모호한 표현과 메타데이터에 없는 표현이 통과하지 않는 반대 시험도 둔다.

완료는 다음 조건을 모두 만족할 때만 인정한다.

- 관련 단위·통합 시험과 전체 회귀 시험이 통과한다.
- 193건만 대시보드 동일 경로로 재실행된다.
- 각 Claim에 공식 조회 여부, 통계표, 좌표, 공식값, 판정, 출처, 남은 실패 이유가 기록된다.
- 결과 보고는 `193건 중 공식값 조회 도달 건수`, `판정 건수`, `남은 사유별 건수`만 사용한다.
- 특정 문장이나 Claim ID를 조건으로 한 운영 코드가 없다.
