# 고용 증감액 Claim 재분류 설계

## 문제

고용 기사에서 `전년 같은 달보다 1만9000명 감소`처럼 변화량을 말했는데도, 외부 구조화 결과가 계산 방식을 `현재값 직접 비교`로 저장한 2건이 있다. 공식 좌표와 현재 공식값은 찾았지만, 감소량을 현재 취업자 수와 비교했기 때문에 최종 판정이 틀렸다.

## 해결 원칙

- 전체 1,542건이나 고용 17건을 다시 돌리지 않는다.
- 이번 묶음은 잘못 분류된 증감액 2건만 처리한다.
- 특정 Claim ID나 문장을 운영 코드에 넣지 않는다.
- 원문, 해당 수치 조각, 비교 기준, 증가·감소 방향이 모두 확인될 때만 계산 방식을 고친다.
- 공식값과 계산 결과는 만들거나 추정하지 않고 KOSIS 공식 API와 Python 계산만 사용한다.

## 안전한 재분류 조건

다음 조건을 모두 만족할 때만 `현재값 직접 비교`를 `두 기간 차이 계산`으로 바꾼다.

1. 원문에서 분리한 대상 수치 조각이 제공된다.
2. Claim 값과 단위가 그 수치 조각에 실제로 존재한다.
3. 비교 방식이 전년·전월·전분기 대비 중 하나다.
4. 원문에 증가 또는 감소를 뜻하는 표현이 있다.
5. 증가·감소 방향 슬롯이 원문 표현과 일치한다.
6. 단위가 비율 자체가 아닌 인원·건수·금액 등 변화량 단위다.

조건을 만족하면 계산 방식을 `DIFFERENCE`로 바꾸고, 두 계산 항은 기사나 LLM 값이 아니라 공식 Evidence에서 가져오도록 기록한다. 조건이 하나라도 부족하면 기존 Claim을 자동 승격하지 않는다.

## 공식 검증 흐름

재분류된 Claim은 별도 판정기가 아니라 기존 공통 공식 엔진으로 돌아간다.

```text
재분류된 Claim
→ Semantic Standard
→ KOSIS Catalog·공식 메타데이터
→ Hard Guard·좌표 확정
→ 현재 기간 공식값 조회
→ 전년 같은 기간 공식값 조회
→ 공표정보 확인
→ Python으로 현재값 - 과거값 계산
→ 기사에 적힌 증가·감소량과 비교
→ Verdict
```

기사에는 감소량을 양수 크기로 쓰는 경우가 많다. Python 계산값은 감소 시 음수이므로, Claim의 방향이 `감소`일 때만 절댓값 크기로 비교한다. 실제 계산 방향이 Claim 방향과 반대면 일치로 인정하지 않는다.

## 저장된 2건의 처리

- 기존 Registry 원본은 변경하지 않는다.
- 선택한 2건만 읽어 재분류된 작은 Registry를 새로 만든다.
- 재분류 전후 계산 방식, 비교 방식, 방향, 대상 수치 조각, 변경 사유를 CSV에 남긴다.
- 재분류된 Registry만 기존 bounded 실행기로 공식 API에 전달한다.
- 결과 CSV에는 두 기간 공식 좌표·값, 공식 URL, 응답 해시, 공표 근거, Python 계산값, 최종 상태를 남긴다.

## 완료 기준

1. 일반화된 재분류 규칙과 잘못된 승격 방지 테스트가 통과한다.
2. 인원 감소량도 두 공식값의 차이로 계산되고 방향이 검증된다.
3. 선택한 2건만 실제 KOSIS 공식 API를 통과한다.
4. 두 기간의 공식값·공표정보·Python 계산·판정이 결과에 보존된다.
5. 개선 전후 CSV와 묶음 완료 판정이 생성된다.
6. 관련 테스트와 전체 단위 테스트가 통과하고 변경을 커밋·푸시한다.
