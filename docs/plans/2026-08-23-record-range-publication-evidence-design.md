# 기록 비교 범위 공표 근거 설계

## 목적

`역대 최대·최소` Claim이 과거 전체 공식값을 비교할 때, 오래된 각 기간의 보도자료를 모두 찾지 못해 중단되는 문제를 해결한다. 기사 대상 기간의 공식 발표와 KOSIS 값별 최종수정일을 결합하여, 기사 시점에 사용 가능했던 공식 시계열인지 추정 없이 확인한다.

## 확인된 문제

- 현재 경로는 KOSIS 통계설명 API에서 공표주기·공표시기·공표방법을 조회한다.
- 설명에 공식 발표 URL이 있으면 해당 문서를 확인하고, 없거나 대상 기간과 다르면 공식 작성기관 보도자료를 검색한다.
- 같은 고용 통계의 2010·2020·2025년 6월 발표일은 공식 검색으로 확인됐다.
- 1999~2005년 6월의 개별 보도자료는 현재 공식 검색에서 확인되지 않았다.
- 기록 비교는 첫 과거 기간부터 개별 공표일을 요구하므로, 27개 공식값 요청 계획을 만들고도 첫 기간에서 `AS_OF_UNAVAILABLE`로 중단된다.

## 선택한 방식

기록 비교에는 `계산 범위 공표 근거`를 사용한다.

1. 동일한 표·항목·차원·주기의 과거 전체 값을 KOSIS 공식 API로 한 번 조회한다.
2. 계산 범위의 마지막 기간, 즉 기사 Claim의 대상 기간에 해당하는 공식 발표자료를 조회한다.
3. 공식 발표 제목·본문이 대상 기간과 일치하고 정확한 발표일이 확인돼야 한다.
4. 발표일이 기사 날짜보다 늦으면 해당 값은 기사 시점에 이용 가능하지 않았으므로 보류한다.
5. 반환된 모든 값의 `LST_CHN_DE`를 확인하고, 하나라도 기사 날짜보다 늦으면 기사 이후 수정된 현재값일 수 있으므로 보류한다.
6. 전체 값과 위 근거가 모두 확인된 경우에만 Python으로 최대·최소를 계산한다.

`LST_CHN_DE`는 최초 공표일로 사용하지 않는다. 대상 기간의 공식 발표일이 공표 근거이며, `LST_CHN_DE`는 현재 API 값이 기사 이후 변경된 값이 아닌지 확인하는 보조 안전장치로만 사용한다.

## 적용 범위

- `RECORD_HIGH`와 `RECORD_LOW` 계산에만 적용한다.
- 직접값, 증감률, 차이, 비중 등 다른 계산의 공표일 계약은 변경하지 않는다.
- 특정 Claim ID나 고용률 문장에 의존하지 않는다.
- 같은 공식 좌표와 연속된 비교 기간으로 구성된 기록 계산 계획에 일반 적용한다.

## 구성요소

### 기록 범위 공식값 조회

기존 `fetch_many`의 KOSIS 범위 요청을 재사용한다. 응답 개수, 기간, 표·항목·차원이 계산 계획과 정확히 일치해야 한다. 실제 범위 요청 URL, 조회시각, 응답 해시를 보존한다.

### 대상 기간 공식 발표 조회

기존 `KosisPublicationLookup`으로 계산 범위의 마지막 기간을 조회한다. 다음 공식 경로를 그대로 사용한다.

1. KOSIS 통계설명 API
2. 통계설명의 공식 발표 URL
3. 등록된 공식 작성기관 보도자료 검색

재시도와 대체 공식 경로를 모두 수행한 뒤에도 날짜를 확인하지 못하면 `AS_OF_UNAVAILABLE`, 외부 요청 자체가 실패하면 `PUBLICATION_FETCH_FAILED`로 구분한다.

### 값별 최종수정일 검사

KOSIS 범위 응답의 각 행에서 `LST_CHN_DE`를 읽는다.

- 날짜 형식이 잘못됐거나 비어 있으면 보류한다.
- 기사 날짜보다 늦으면 보류한다.
- 기사 날짜와 같거나 이전이면 범위 공표 근거의 보조 조건을 통과한다.

## 명시적 감사 기록

공표 근거가 개별 과거 기간의 최초 발표처럼 보이지 않도록 다음을 기록한다.

- 근거 범위: `PERIOD` 또는 `CALCULATION_RANGE`
- 기준 기간: 공식 발표를 조회한 기사 대상 기간
- 적용 시작·종료 기간
- 공식 발표일과 공식 발표 URL
- 공식 발표자료 내용 해시와 조회시각
- 각 공식값의 KOSIS 최종수정일
- 실제 KOSIS 범위 응답 URL과 내용 해시

## 처리 흐름

```text
RECORD_HIGH/LOW 계산 계획
→ 동일 좌표의 전체 기간 KOSIS 값 범위 조회
→ 마지막 기간의 공식 발표 조회
→ 공식 발표일 ≤ 기사 날짜 확인
→ 모든 값의 최종수정일 ≤ 기사 날짜 확인
→ 전체 값 누락 여부 확인
→ Python 최대·최소 계산
→ Verdict와 범위 공표 근거 저장
```

## 실패 처리

- 대상 기간 공식 발표 요청 실패: `PUBLICATION_FETCH_FAILED`
- 대상 기간 공식 발표일 미확정: `AS_OF_UNAVAILABLE`
- 발표일이 기사 이후: `AS_OF_UNAVAILABLE`
- 값의 최종수정일 누락·형식 오류·기사 이후: `AS_OF_UNAVAILABLE`
- 공식값 범위 요청 실패: `FETCH_FAILED`
- 기간별 공식값 누락: 기존 공식값 누락 상태로 보류

어떤 경우에도 공표일이나 최종수정일을 일정 문구로 계산하거나 LLM으로 생성하지 않는다.

## 검증 기준

1. 기록 비교만 범위 공표 경로를 사용한다.
2. 대상 기간 공식 발표를 한 번만 조회한다.
3. 27개 과거 기간을 각각 보도자료 검색하지 않는다.
4. 모든 값의 `LST_CHN_DE`가 기사 날짜와 비교된다.
5. `LST_CHN_DE`가 공표일 필드로 저장되지 않는다.
6. 누락·기사 이후 수정·발표일 미확정은 모두 fail-closed로 보류된다.
7. 공식 URL·조회시각·응답 해시·범위가 CSV/JSONL에 남는다.
8. 대표 Claim `A02558_7` 한 건을 실제 공식 API로 재실행한다.
9. 대표 Claim은 27개 공식값이 완전하면 Python 기록 계산과 Verdict까지 도달한다.
10. 전체 테스트와 독립 코드 리뷰에서 Critical/Important 문제가 없어야 한다.

전체 1,542건 재실행은 이번 묶음의 완료 조건이 아니다. 대표 기록 Claim의 실제 공식 조회와 감사 결과를 확보한 뒤 다음 문제 묶음으로 이동한다.
