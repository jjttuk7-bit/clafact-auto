# 남은 Claim 세부 문제 분류 설계

## 목적

통합 진행 원장에 남아 있는 1,518건을 큰 문제 묶음 일곱 개보다 더 작은 해결 단위로 나눈다. 전체 파이프라인을 다시 실행하지 않고 기존 실행 결과, 12개 항목 상태, 원문에 명시된 표현만 사용한다.

## 선택한 방식

세부 분류를 별도 임시 파일에만 저장하지 않고 통합 원장 생성 과정에 연결한다. 따라서 원장을 다시 만들 때마다 같은 입력은 같은 세부 유형으로 분류되며 새 실행 결과가 들어오면 최신 단계에 맞춰 자동으로 갱신된다.

언어모델은 이 1차 분류에 사용하지 않는다. 중단 단계와 공식 reason code를 가장 먼저 사용하고, 원문의 기록·증감·상대기간 표현과 12개 항목의 누락 상태는 하위 유형을 나누는 보조 근거로만 사용한다.

## 원장에 추가할 내용

- `세부문제유형`: 프로그램에서 사용하는 안정적인 유형 코드
- `세부문제설명`: 사람이 이해할 수 있는 쉬운 문제 설명
- `해결방법`: 다음 구현 묶음에서 수행할 작업
- `처리우선순위`: 남은 건수와 앞 단계 여부를 반영한 순서
- `대표실행묶음`: 같은 유형에서 먼저 실행할 최대 20건의 묶음 번호

완료된 24건은 세부문제유형을 `완료`로 기록하고 새 실행 대상으로 뽑지 않는다.

## 분류 원칙

1. 최신 중단 사유와 단계가 있으면 이를 원본의 오래된 사유보다 우선한다.
2. 한 Claim에는 현재 해결할 세부 유형을 정확히 하나만 지정한다.
3. 문맥 단계에서는 기록 주장, 여러 수치, 비교 표현, 상대기간, 12개 항목 누락을 우선순위에 따라 구분한다.
4. 공식 경로, 의미, 값·발표 단계는 이미 기록된 안정적인 사유 코드를 그대로 세분화한다.
5. 필수 조건과 좌표 단계는 누락된 12개 항목을 이용해 기간·단위·차원·일반 후보 문제로 구분한다.
6. 계산 단계는 원문에서 기록 비교, 증감률, 차이, 직접값 순으로 계산 유형을 구분한다.
7. 근거가 부족하면 억지로 구체화하지 않고 해당 단계의 일반 세부 유형으로 남긴다.

## 데이터 흐름

```text
기존 1,542행 원장
→ 최신 상태·단계·사유 확정
→ 12개 항목 누락과 원문 패턴 확인
→ 세부 유형·설명·해결방법 결정
→ 유형별 빈도순 우선순위 부여
→ 유형별 대표 Claim 최대 20건 지정
→ 통합 CSV와 요약 JSON 저장
```

## 안전장치와 완료 기준

- 출력은 정확히 1,542행이어야 한다.
- Claim 번호는 중복되거나 누락되면 안 된다.
- 완료 24건과 남은 1,518건의 합계가 유지되어야 한다.
- 남은 1,518건은 세부 유형 누락이 0건이어야 한다.
- 세부 유형별 건수 합계는 1,518건이어야 한다.
- 대표 실행 묶음은 유형마다 최대 20건이며 같은 Claim이 두 유형에 들어가면 안 된다.
- 이번 목표에서는 KOSIS API를 새로 호출하지 않는다. 다음 해결 목표에서 대표 묶음만 실제 파이프라인으로 실행한다.
