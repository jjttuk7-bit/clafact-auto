# Claim Type Contract Design

## Goal

Apply the canonical Claim definition as an executable AUTO-admission contract without making existing Registry records unloadable or modifying source gold data.

## Decision

Use a pure domain validator that accepts `ClaimSchema` and returns a typed `PASS` or `HOLD` decision. Pydantic continues to validate storage shape. The parser and dynamic E2E runner invoke the domain validator before Semantic Mapping or KOSIS search. Invalid `AUTO_OK` claims become auditable HOLD results instead of validation exceptions.

Rejected alternatives:

- Construction-time Pydantic rejection would make historical and review records unloadable.
- Mutating `parse_status` inside a Pydantic model validator would create hidden side effects and make source/derived state difficult to audit.

## Common AUTO contract

Every `AUTO_OK` Claim requires non-empty `indicator`, numeric `value`, non-empty `unit`, non-empty `time`, and a supported `calculation`. Existing `HOLD` and `HUMAN_REVIEW` Claims are preserved and are not promoted by this validator.

## Type-specific contract

- `DIRECT_VALUE`: common fields are sufficient.
- `GROWTH_RATE`: percent-compatible unit, one supported comparison type, and `INCREASE` or `DECREASE` direction.
- `DIFFERENCE`: comparison type, current/reference operands, operand unit, and direction.
- `SHARE`: percent-compatible unit and an explicit part-to-whole comparison contract.
- `RATIO` / `MULTIPLE`: an explicit numerator/denominator or current/reference comparison contract.
- `RANK`: positive integer rank, rank unit, one target dimension, ordering, and population scope.
- `THRESHOLD`: supported operator, numeric threshold, and compatible threshold unit.

Where historical representations do not yet satisfy these contracts, the Claim is routed to HOLD. The validator does not guess or rewrite operands.

## Result contract

The decision records:

- `status`: `PASS` or `HOLD`
- stable `reason_code`
- ordered `missing_slots`
- optional non-secret detail for operator/unit/type mismatches

Missing slots use only the canonical 12-slot names. Unsupported calculations and incompatible units use fixed reason codes. Provider text and API secrets are never copied into the decision.

## Integration

1. `parse_claim` applies the validator after normalization and relative-time resolution.
2. `run_dynamic_e2e_batch` applies the same validator to imported/Gold Claims before Semantic Mapping.
3. Single-Claim Streamlit uses `parse_claim`; batch uses the dynamic runner, so both paths share the contract.
4. Original Registry files remain unchanged; only derived runtime results receive HOLD routing.

## Safety and compatibility

- No Profile dependency is introduced.
- Hard Guard remains after Claim admission and before Semantic Matching.
- Official values remain outside the Claim and are never generated by an LLM.
- Existing non-AUTO records remain loadable.
- Existing AUTO records may move to HOLD at runtime when they violate the canonical Claim definition; this is the intended safety correction.
