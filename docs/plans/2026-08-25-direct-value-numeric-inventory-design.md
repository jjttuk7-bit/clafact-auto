# 직접값 381건 원문 수치 목록화 설계

## 목적

`08_직접값` 동결 입력 381건의 각 원문에 등장하는 숫자 표현을 원문 위치와 함께 빠짐없이 기록한다. 이 결과는 다음 작업인 숫자 역할 분류의 입력이며, 이번 작업에서는 대상값·기간·연령 등의 의미를 확정하지 않는다.

## 검토한 방식

1. 기존 통계값 추출기 재사용: `%`, `명`, `대`, `달러` 등만 찾아 연도·월·기간·순위와 단위 없는 숫자를 누락하므로 부적합하다.
2. 외부 LLM 목록화: 표현 범위와 누락 여부를 결정론적으로 재검사하기 어렵고 같은 입력의 재현성이 낮아 부적합하다.
3. 원문 위치 기반 결정론적 목록화: 모든 숫자 문자를 기준으로 가장 긴 표현 범위를 만들고 시작·끝 위치를 보존할 수 있어 채택한다.

## 출력 계약

- 입력 Claim 1건당 결과 CSV 1행을 만든다.
- `수치목록JSON`에는 발견 순서대로 `mention_id`, `expression`, `start`, `end`, `context`, `role_status`를 기록한다.
- `role_status`는 이번 단계에서 모두 `미분류`로 둔다.
- 아라비아 숫자뿐 아니라 단위와 결합된 한글 수량 표현(`한 달`, `두 배`, `석 달`)도 제한된 문법으로 기록한다.
- 원문 숫자의 시작·끝 위치는 Python 문자열 인덱스이며 `원문[start:end] == expression`을 강제한다.

## 추출 경계

- 날짜: `2025-01-01`, `2024년`, `12월`, `15일`
- 통계값: `2804만1000명`, `533억6000만달러`, `2.1%`, `-47만3000명`
- 범위: `3~4%`, `1∼2개월`
- 맥락 숫자: `20대`, `상위 7개`, `737`
- 제한된 한글 수량: `한 달`, `두 배`, `석 달`, `절반`

## 실패 차단

- Claim번호 누락·중복, 원문 누락, 입력 381건 불일치는 실패한다.
- 원문의 숫자 문자 중 추출 범위에 포함되지 않은 위치가 하나라도 있으면 실패한다.
- 추출 표현과 원문 위치가 일치하지 않으면 실패한다.
- 결과 CSV와 JSONL의 Claim 수·내용·해시가 다르면 완료하지 않는다.

## 완료 조건

- 입력 Claim 381건, 결과 Claim 381건, 고유 Claim번호 381개
- 원문 수치 목록 보유 Claim 381건
- 숫자 문자 미포함 위치 0개
- 위치 불일치 0개
- 실패한 검사항목 0개
