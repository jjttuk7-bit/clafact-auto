# 직접값 좌표·공표 공통 규칙 설계

## 목적

직접값 230건을 다시 분류하거나 전량 반복 실행하지 않는다. 현재 원장에서 실제 병목으로 확인된 좌표 실패 92건과 공표 확인 실패 18건만 대상으로, 특정 Claim이나 통계표 결과를 고정하지 않는 공통 규칙을 기존 공식 검증 파이프라인에 연결한다.

## 선택한 방식

세 가지 후보 중 **분리 검증 방식**을 사용한다.

1. Claim별 수동 좌표 등록: 빠르지만 새 뉴스에 일반화되지 않아 제외한다.
2. 230건 전체 반복 실행: 결과 관찰은 쉽지만 시간·API 호출을 낭비하고 최종 검증 집합이 오염되어 제외한다.
3. 발견용→중간검증용→최종미사용 순서: 발견용에서 원인을 규칙화하고, 중간검증용으로 일반화를 확인한 뒤, 최종미사용 Claim은 마지막에 한 번만 실행한다.

## 데이터 경계

- 발견용 집합: 원인 조사와 규칙 설계에 사용한다.
- 중간검증용 집합: 구현 후에만 실행하고 규칙의 재현성을 확인한다.
- 최종미사용 집합: 규칙 수정에 사용하지 않고 마지막 수용 시험에서 한 번만 실행한다.
- 모든 대상 ID·원문 해시·기준 결과를 실행 전에 고정한다.

## 공통 규칙의 범위

### 좌표 규칙

KOSIS Catalog 검색과 공식 메타데이터 조회 결과를 이용해 다음을 일반적으로 처리한다.

- Claim 지표·단위·주기와 호환되는 표만 남긴다.
- 지역·대상·분류 차원은 Claim 슬롯과 공식 멤버 코드가 일치할 때만 확정한다.
- 공식 구조 안에서 증거 셀이 정확히 하나일 때만 자동 선택한다.
- 민간 계약금·기업 가격·정책 기준·전망처럼 KOSIS 관측 통계가 아닌 값은 공식 조회 실패와 구분된 사유로 제외한다.
- 후보가 여러 개면 강제 선택하지 않고 실패 단계와 후보 차이를 기록한다.

### 공표 규칙

- KOSIS 통계설명 API의 공표주기·공표시기·공표방법을 먼저 조회한다.
- 대상 기간의 공표 여부는 KOSIS 또는 공식 작성기관의 대상 기간별 발표자료로 확인한다.
- LST_CHN_DE는 수정일로만 사용하고 최초 공표일로 간주하지 않는다.
- 공식 URL·조회시각·내용 해시·대상 기간이 모두 남을 때만 공표 확인으로 인정한다.

## 실행 흐름

기존 단일 Core Engine 흐름을 바꾸지 않는다.

`Claim 구조화 → 의미 표준 → Catalog API → Metadata API → Hard Guard → 좌표 규칙 → Value API → 공표 규칙 → Python 판정`

Streamlit·배치·CLI는 모두 같은 서비스와 같은 규칙을 호출한다.

## 완료 조건

- 발견용에서 만든 규칙이 중간검증용과 최종미사용 Claim에도 코드 수정 없이 적용된다.
- 최종미사용 Claim은 마지막에 한 번만 실제 공식 API로 실행된다.
- 신규 뉴스에서도 동일 규칙으로 공식 좌표·값·공표 근거·판정이 생성된다.
- 공식 판정 완료 수가 기준 15건보다 실제 증가한다.
- 미해결 건은 정확한 공식 조회 단계와 사유로 남는다.
- 230행 통합 CSV에 개선 전후, 적용 규칙, 좌표, URL, 해시, 공표 확인을 누적한다.
