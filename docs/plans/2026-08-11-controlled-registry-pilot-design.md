# Controlled Registry Pilot Design

## Purpose

Run a cost-bounded, auditable first verification batch against 50 immutable Claim Registry source records. The pilot validates the general multi-evidence engine; it does not alter registry source data or tune the system for a single example.

## Selected approach

Use the OpenAI strict function-call extractor for each selected source sentence, then deterministically normalize the returned indicator against `concept_seed_v1.json`. Persist a derived Claim Registry JSONL and concept sidecar JSON before invoking the profile-first E2E engine.

The source registry remains read-only. The command selects the first 50 valid records in source order unless a `--limit` override is explicitly supplied. Every source record produces one auditable result: extraction/normalization failures become a derived `HOLD` record with a reason code, never a fabricated value or forced semantic match.

## Data flow

```text
immutable claim_registry.jsonl (50 selected source records)
  -> OpenAI emit_claim function call (one output / source sentence)
  -> deterministic concept_seed_v1 normalization
  -> derived_registry.jsonl + concepts.json + extraction_report.json
  -> profile-first E2E batch
  -> e2e_results.jsonl + coverage_report.json + review_queue.jsonl
```

The derived Claim preserves the original `article_id`, `sentence_id`, and publication date. Its source sentence is retained verbatim. Result paths are caller-supplied and rejected when they point at the source registry directory.

## Calculation and traces

The planner infers the approved `GROWTH_RATE` calculation only when the extracted comparison basis is exactly `전년 동월 대비`; it then resolves current and prior-year monthly cells. All other absent/unsupported calculations route to `HOLD`.

Every E2E row, including all early HOLD paths, receives one standardized execution trace. The trace distinguishes parser/semantic/profile/evidence/calculation stages without exposing credentials or raw provider responses.

## Failure handling and safety

- Only `OPENAI_API_KEY` from the process environment is used; no key is stored or logged.
- Provider, schema, normalization, missing-profile, evidence, and value failures are retained as reason-coded HOLD rows.
- No KOSIS value is generated by the model. Official values continue through snapshot/API adapters and deterministic calculation only.
- The tool writes only derived output files. It does not update the input registry, semantic standard, or operational data.

## Verification

Tests cover limit selection, provider-error HOLD conversion, deterministic concept sidecar creation, growth inference, and early-HOLD trace creation. Before committing, run the focused tests and the full pytest suite. The live 50-record run is reported with its coverage and review-queue counts, not asserted as a unit-test substitute.
