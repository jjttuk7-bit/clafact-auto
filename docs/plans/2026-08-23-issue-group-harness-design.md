# 문제 Claim 구간 실행 하네스 설계

## 목적

1,542개 Claim을 매번 전체 실행하지 않고, 현재 결과에서 각 Claim의 가장 먼저 해결할 문제를 하나 지정한 뒤 같은 문제끼리 묶어 관련 단계만 소량 재실행한다. 모든 개선 결과는 CSV 작업대장에 누적하고, 각 묶음의 완료 기준을 통과하기 전에는 다음 단계나 최종 전체 실행을 허용하지 않는다.

## 선택한 구조

기존 `unified_claim_pipeline`과 v3 공식 조회 엔진은 판정 엔진으로 그대로 사용한다. 새 하네스는 이 엔진 앞에 놓이는 실행 제어 계층이며, 공식값을 만들거나 판정을 대신하지 않는다.

```text
기준 실행 결과
→ 대표 문제 자동 분류
→ 묶음별 CSV 작업대장 생성
→ 묶음과 표본 선택
→ 허용된 단계만 실행
→ 개선 전후 결과 기록
→ 묶음 완료 기준 판정
→ 모든 묶음 완료 후 최종 전체 실행 1회 허용
```

## 대표 문제 묶음

각 Claim은 아래 묶음 중 하나만 대표 문제로 가진다. 여러 문제가 관찰되면 파이프라인에서 가장 먼저 멈춘 문제를 대표 문제로 정하고 나머지는 보조 문제로 기록한다.

| 코드 | 쉬운 이름 | 대표 실패 사유 | 실행 상한 |
| --- | --- | --- | --- |
| `CONTEXT` | 기사 문맥·Claim 재분류 | `CONTEXT_REQUIRED` 및 입장 전 실패 | 12개 항목 작성과 재입장 |
| `OFFICIAL_PATH` | 공식 통계표·항목 조회 | `KOSIS_CATALOG_UNAVAILABLE`, `KOSIS_METADATA_UNAVAILABLE` | 공식 구조 정보 조회 |
| `HARD_GUARD` | 필수 조건 비교 | `NO_HARD_GUARD_CANDIDATE` | 필수 조건 비교 |
| `COORDINATE` | 통계표 좌표 결정 | `NO_EVIDENCE_COORDINATE_CANDIDATE` | 좌표 결정 |
| `SEMANTIC` | 의미 후보 구분 | `LOW_SEMANTIC_SCORE`, `AMBIGUOUS_MARGIN`, `CONCEPT_NOT_FOUND` | 의미 후보 비교 |
| `CALCULATION` | 계산 방법 구성 | `CALCULATION_EVIDENCE_PLAN_UNRESOLVED`, `CALCULATION_FAILED` | 계산 계획·계산 |
| `VALUE_PUBLICATION` | 공식값·발표정보 조회 | `FETCH_FAILED`, `AS_OF_UNAVAILABLE`, `PUBLICATION_FETCH_FAILED` | 공식값·발표정보·판정 |
| `REGRESSION` | 현재 성공 보호 | `AUTO` | 전체 경로 회귀검사 |
| `UNCLASSIFIED` | 아직 분류되지 않음 | 알려지지 않은 사유 | 실행 금지 |

## 단계 제한

하네스는 묶음마다 실행 가능한 단계의 시작과 끝을 명시한다. 선택한 묶음의 상한 뒤 단계는 호출하지 않는다. 공식 조회 단계에서 `HOLD`를 만들 때는 실행 계약에 따라 실제 요청·재시도·대체 경로의 결과가 추적에 있어야 한다. 기사 문맥처럼 공식 조회 전 단계에서 멈춘 경우에는 공식 조회 실패 `HOLD`로 기록하지 않고 `재분류 필요` 상태로 보존한다.

기본 실행 단위는 20건이며 사용자가 1~50건 범위에서 바꿀 수 있다. 하네스는 묶음을 지정하지 않은 실행, 50건을 초과하는 실행, 미분류 Claim 실행을 거부한다.

## CSV 작업대장

하네스는 UTF-8 BOM CSV를 생성한다.

- `claim_issue_master.csv`: 모든 Claim의 현재 상태와 대표 문제
- `groups/<문제코드>.csv`: 선택·실행 가능한 묶음별 작업대장
- `runs/<실행번호>.csv`: 해당 구간 실행의 개선 전후 결과
- `group_summary.csv`: 묶음별 전체 수, 시도 수, 개선 수, 남은 수, 완료 여부

핵심 열은 Claim 번호, 기사 번호, 원문, 12개 항목 상태, 현재 중단 단계, 현재 사유, 대표 문제, 보조 문제, 다음 실행 단계, 개선 전 상태·사유, 개선 후 상태·사유, 공식 통계표, 공식값 출처, 실행 횟수, 코드 버전, 기록 시각이다.

행은 Claim 번호로 갱신하며 실행 때마다 새 행을 무한 추가하지 않는다. 실행 이력은 별도 `runs` CSV에 보존한다. 묶음 합계와 종합 파일 행 수는 자동 검증한다.

## 완료문과 전체 실행 잠금

각 묶음은 설정된 표본을 재실행한 뒤 다음을 만족해야 완료할 수 있다.

1. 모든 대상 Claim에 개선 전후 기록이 있다.
2. 실패가 더 앞 단계로 후퇴하지 않는다.
3. 공식 조회를 수행한 결과에는 요청 단계와 출처가 남는다.
4. 남은 실패는 정확한 단계와 쉬운 사유로 다시 분류된다.
5. 묶음의 합격 기준을 충족한다.

최종 전체 실행 명령은 모든 필수 묶음의 완료 상태와 그 상태를 만든 코드·데이터 버전이 현재 버전과 일치할 때만 허용한다. `--allow-final-full-run`을 명시해야 하며, 일반 구간 실행 명령에는 전체 Registry를 선택하는 기능을 제공하지 않는다.

## 오류 처리

- 기준 결과와 원본 Registry의 Claim 번호가 맞지 않으면 분류를 중단하고 누락·중복 목록을 기록한다.
- 알 수 없는 사유는 임의로 가까운 묶음에 넣지 않고 `UNCLASSIFIED`로 보낸다.
- 공식 API 장애는 후보 없음으로 바꾸지 않는다.
- 구간 실행이 중단돼도 완료된 Claim 결과는 보존하며 같은 실행번호로 재개할 수 있다.
- 코드 또는 의미 기준이 바뀌면 이전 완료문은 무효가 된다.

## 시험 전략

테스트를 먼저 작성한다.

1. 모든 알려진 실패 사유가 정확한 대표 문제로 분류되는지 시험한다.
2. Claim 하나에 대표 문제가 정확히 하나인지 시험한다.
3. 묶음별 단계 상한과 최대 50건 제한을 시험한다.
4. 허용되지 않은 다음 단계가 호출되지 않는지 가짜 단계 함수로 시험한다.
5. 종합·묶음·실행 CSV의 열, 행 수, 한글 인코딩, 합계를 시험한다.
6. 완료문이 없거나 버전이 다르면 전체 실행이 차단되는지 시험한다.
7. 기존 파이프라인 회귀시험과 실제 공식 API 소량 승인시험을 실행한다.

## 적용 순서

1. 기준 실행 결과를 읽어 대표 문제를 분류한다.
2. 종합·묶음별 CSV를 생성한다.
3. 묶음 선택과 실행 제한을 구현한다.
4. 기존 단계 실행기와 연결한다.
5. 전후 결과와 완료문을 구현한다.
6. 실제 기준 결과로 1,542건 분류를 생성한다.
7. 첫 구간인 기사 문맥 문제 중 본문 사용 가능 Claim 20건을 실행한다.
8. 모든 묶음 완료 후에만 전체 실행을 한 번 수행한다.
