# 직접값 부호·방향 보존 설계

## 목표

직접값 381건에서 확정된 원문 대상 숫자에 연결된 흑자·적자, 증가·감소 방향을 보존한다. 원래 기사값은 변경하지 않고 별도의 계산용 부호값과 원문 근거를 기록한다.

## 실제 입력에서 확인한 문제

- 원문 대상값 확정: 365건, 미확정: 16건
- 증감값으로 분류된 대상: 67건
- 무역수지 흑자·적자 표현: 6건, 무역수지이지만 극성 표현이 없는 비교값: 1건
- 저장 방향 누락 예: `수출은 10.3% 급감했다`인데 condition.direction이 비어 있다.
- 다른 숫자의 방향으로 오염된 예: `31만명 이상 늘어 ... 청년층은 14만6000명 줄어`의 대상 31만명에 DECREASE가 저장돼 있다.
- 숫자 역할 자체가 잘못된 예: `2017년 3686만명을 정점으로 하락`의 3686만명은 감소량이 아니라 당시 수준값이다.

## 선택한 방식

대상 숫자의 정확한 원문 위치를 기준으로 같은 절 안의 방향 표현만 연결하는 결정론적 규칙을 사용한다.

1. 원문 대상 연결이 확정된 Claim만 평가한다.
2. 무역수지처럼 부호가 정의된 지표에서 대상 숫자에 직접 붙은 `흑자`는 +, `적자`는 -로 기록한다.
3. 증감값은 대상 숫자 앞뒤의 `증가·감소·상승·하락·늘다·줄다·급증·급감` 표현을 연결한다.
4. `증가폭·감소폭`처럼 숫자 앞의 의미 명칭을 우선한다. 뒤쪽의 다른 변화 서술이 과거 증감폭의 방향을 덮지 못하게 한다.
5. `정점·수준·기록·까지`와 결합된 숫자는 변화량이 아니라 수준값일 가능성이 있으므로 자동 부호 적용을 중단하고 숫자 역할 재검토로 보낸다.
6. 원래 claim.value는 보존한다. `signed_target_value`, `source_direction`, `source_polarity`, 근거 문구와 위치를 별도 보강자료에 저장한다.
7. 확실한 원문 방향이 저장 condition과 다르면 원문 방향을 사용하되, 이전 방향과 교정 사유를 감사 기록에 남긴다.
8. 원문 방향을 하나로 확정하지 못하면 강제 선택하지 않고 공식조회 전 재검토 사유로 중단한다.

## 대안과 선택 이유

### 전체 문장의 방향 단어 사용

구현은 간단하지만 한 문장에 증가와 감소가 함께 있으면 다른 숫자의 방향을 적용한다. 실제 381건에서 이미 이런 오염이 확인돼 제외한다.

### LLM으로 381건 재추출

복잡한 문장을 처리할 수 있지만 실행할 때마다 결과가 달라질 수 있고, 부호 적용 근거를 재현하기 어렵다. 원문 위치가 이미 확정된 현재 단계에는 사용하지 않는다.

### 대상 위치 기반 결정론적 규칙

같은 패턴에 반복 적용되고 근거 위치를 저장할 수 있다. 애매한 문장은 다음 단계로 넘길 수 있어 이 방식을 채택한다.

## 결과 상태

- `SIGN_DIRECTION_CONFIRMED`: 저장 방향과 원문 방향이 일치한다.
- `SOURCE_DIRECTION_RECOVERED`: 저장 방향이 비었지만 원문에서 확정했다.
- `STORED_DIRECTION_CONFLICT_CORRECTED`: 다른 숫자 때문에 잘못 저장된 방향을 원문 기준으로 교정했다.
- `BALANCE_POLARITY_CONFIRMED`: 흑자·적자 극성과 계산용 부호를 확정했다.
- `NOT_APPLICABLE_LEVEL_VALUE`: 수준값이라 별도 부호 적용이 필요 없다.
- `TARGET_ROLE_REVIEW_REQUIRED`: 증감값으로 저장됐지만 실제로는 수준값 가능성이 높다.
- `DIRECTION_AMBIGUOUS`: 해당 대상 숫자의 방향을 하나로 확정하지 못한다.
- `NOT_EVALUATED_TARGET_UNGROUNDED`: 앞 단계에서 대상 숫자가 확정되지 않았다.

## 파이프라인 적용

- 원문 방향이 확정된 경우 condition.direction 또는 condition.polarity를 실행용 Claim에 보강한다.
- 원래 기사값과 원래 condition은 결과 CSV·JSONL에 그대로 남긴다.
- `TARGET_ROLE_REVIEW_REQUIRED`와 `DIRECTION_AMBIGUOUS`는 KOSIS 실패가 아닌 공식조회 전 구조화 사유로 중단한다.
- 계산용 부호값은 이후 Python 계산 단계에서만 사용하며, 이 단계에서는 KOSIS 판정 성공으로 계산하지 않는다.

## 완료 기준

1. 381건 모두 결과 행이 있고 Claim 번호 중복이 없다.
2. 부호가 필요한 모든 Claim에 방향 또는 극성, 계산용 부호값, 원문 근거 위치가 있다.
3. 다른 숫자의 방향을 대상값에 적용한 사례가 0건이다.
4. 수준값 의심 사례를 자동 증감값으로 통과시킨 건수가 0건이다.
5. 결과 CSV·보강 JSONL·실행 이력·검증 이력·결과 보고서가 생성된다.
6. 통합 파이프라인 회귀시험과 전체 단위시험 결과가 기록된다.
