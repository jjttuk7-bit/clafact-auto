# 직접값 복수 Claim 분리 설계

## 목표

숫자 역할이 안전한 직접값 부모 Claim 360건을 보존하면서, 한 문장 안의 여러 통계값이 한 주장에 속하는지 또는 서로 독립된 주장인지 구분한다. 독립 주장은 자식 Claim으로 나누고 각각 12개 슬롯을 다시 구조화해 동일 공식 검증 파이프라인에 재진입시킨다.

## 범위와 계수

- 입력 부모 Claim: 360건
- 현재 정규식 기준 복수 통계 수치 후보: 236건
- 현재 단일 통계 수치 부모: 124건
- OpenAI Structured Output 외부 전송 상한: 236개 부모
- 교정된 사전 탐색 결과가 236개를 초과하면 외부 요청 전에 중단한다.
- 236은 분리 완료 건수가 아니라 기존 탐색기의 사전 후보 수다. 실제 분리 부모 수와 자식 수는 검증된 그룹 결과로 새로 산출한다.

## 확인된 기존 문제

1. `recover_registry_record_v3`는 확정 대상 표현이 있으면 다중 수치 그룹화를 건너뛴다. 이 때문에 첫 번째 숫자만 처리되고 독립된 두 번째 Claim이 유실될 수 있다.
2. `verify_registry_record`는 부모에 저장된 지표·단위 판정을 그룹화보다 먼저 적용한다. 부모 대표값의 오류가 문장 전체를 막아 정상 자식 Claim까지 잃을 수 있다.
3. 수치 탐색기가 `10개월`의 `10개`를 통계값으로 오인한다.
4. 단위 없는 지수 수준값 `116.38`은 탐색하지 못해 물가지수 수준과 상승률을 함께 구조화할 수 없다.
5. 여러 숫자가 있다고 모두 여러 Claim은 아니다. 현재값·비교값·증감값은 한 Claim이고, 환산값도 별도 Claim이 아니다.

## 선택한 구조

### 1. 통계 수치 탐색 교정

- 단위가 더 긴 표현의 일부를 짧은 단위로 잘라 인식하지 않는다. 예를 들어 `개월`을 `개`로, `%포인트`를 `%`로 읽지 않는다.
- 지수라는 원문 근거가 있는 소수 수준값은 통계 수치로 인식한다.
- 연도·월·연령·순위·시계 시각·표본 개수 등 문맥 숫자는 중심 통계값으로 자동 승인하지 않는다.
- 모든 수치는 원문의 시작·끝 위치를 유지한다.

### 2. 그룹화 순서 교정

처리 순서는 다음과 같다.

```text
원문 수치 탐색
→ 복수 통계 수치 여부 확인
→ Structured Output으로 수치 관계 그룹화
→ Python 검증기로 누락·중복·원문 위치 검사
→ 그룹별 자식 Claim 생성
→ 자식 Claim별 12슬롯 재구조화
→ 자식 Claim별 Admission
→ 공식 검증 가능 자식만 v3 공식 엔진 호출
```

- 통계 수치가 하나뿐이면 기존 확정 대상 경로를 그대로 사용한다.
- 통계 수치가 둘 이상이면 확정 대상 하나가 있더라도 먼저 그룹화한다.
- 부모의 지표·단위 판정은 자식 생성 전 문장 전체를 차단하는 근거로 사용하지 않는다.
- 생성된 자식은 자신의 지표·값·단위로 다시 검증한다.

### 3. Structured Output 역할

OpenAI에는 원문과 원문 위치가 확인된 통계 수치 목록만 전송한다. 출력은 기존 `ClaimGroupingPlan` 계약으로 제한한다.

- `MAIN_VALUE`: 자식 Claim의 중심값
- `REFERENCE_VALUE`: 동일 Claim의 비교값
- `CHANGE_VALUE`: 동일 Claim의 증감값
- `EQUIVALENT_VALUE`: 환산값
- `CONTEXT_VALUE`: 기준·설명 수치

Python 검증기는 모든 수치가 정확히 한 번 배정됐는지, 그룹마다 중심값이 하나인지, 존재하지 않는 수치를 만들지 않았는지 확인한다. 모호하거나 계약을 어긴 출력은 공식 조회로 보내지 않는다.

## 부모·자식 연결

각 결과에는 다음을 남긴다.

- 부모 Claim 번호
- 자식 Claim 번호와 순서
- 중심 수치 원문 표현 및 시작·끝 위치
- 같은 Claim에 속한 비교·증감·환산 수치
- 12슬롯 구조화 결과
- 재입장 경로와 중단 사유
- Structured Output 요청·결과 상태, 실행시각, 코드·자료 버전

자식 ID는 부모 원문과 중심 수치 표현으로 결정론적으로 생성한다. 같은 입력을 다시 실행해도 동일해야 한다.

## 오류 처리

- 외부 그룹화 실패: 정해진 횟수만 재시도하고 `CLAIM_GROUPING_PROVIDER_FAILURE`로 기록한다.
- 모호한 관계: `GROUPING_AMBIGUOUS`로 사전 검증 보류한다.
- 수치 누락·중복·가짜 수치: 기존 세부 reason code로 차단한다.
- 외부 전송 부모가 236개를 초과: `APPROVED_EXTERNAL_SCOPE_EXCEEDED`로 실행 전 중단한다.
- 자식 12슬롯 부족: 해당 자식만 정확한 Claim parsing 사유로 보류한다.
- 공식 API 실패: 자식별 실제 공식 단계 reason code를 보존한다.

## 결과 파일

- 부모별 분리 판정 CSV
- 자식 Claim별 상세 CSV
- 전체 구조화 결과 JSONL
- 공식 검증 재입력 Registry JSONL
- 실행 이력 CSV
- 검증 이력 CSV
- 쉬운 용어 결과보고 TXT
- 1단계 7번 완료 체크리스트 JSON

## 완료 기준

1. 입력 부모 360건, 고유 부모 360건, 누락·중복 0건이다.
2. 외부 전송 수가 236개 이하이며 전송 대상과 비대상이 모두 기록된다.
3. 분리 대상으로 판정된 모든 부모에 하나 이상의 자식이 있고 모든 자식에 부모 연결이 남는다.
4. 그룹 결과의 수치 누락·중복·원문 위치 오류가 0건이다.
5. 모호한 그룹이 공식 서비스로 호출된 건수가 0건이다.
6. 정상 자식은 12슬롯 재구조화와 재Admission을 거쳐 공식 엔진 호출 가능 경로에 연결된다.
7. 단일 수치 부모의 기존 확정 대상 경로가 회귀하지 않는다.
8. 결과와 근거가 CSV·JSONL·이력·보고서·체크리스트에 기록된다.

## 이번 단계가 의미하는 것

이 단계 완료는 모든 자식 Claim의 KOSIS 판정 완료를 뜻하지 않는다. 문장 안에서 사라지던 독립 Claim을 복원하고, 각 자식이 자기 12슬롯을 갖고 공식 파이프라인으로 들어갈 수 있게 만드는 완료다. 이후 직접값 재분류와 공식 좌표 단계에서 자식별 실제 해결 건수를 집계한다.
