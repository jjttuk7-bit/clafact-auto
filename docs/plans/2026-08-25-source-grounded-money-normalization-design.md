# 원문 근거 통화 금액 표준화 설계

## 목적

Structured Output이 같은 기사 금액을 서로 다른 배율 단위로 반환해도 원문과 정확히 같은 금액이면 하나의 표준형으로 바꿔 공식 조회까지 진행한다. 특정 Claim ID나 문장을 조건으로 처리하지 않는다.

예시는 다음과 같다.

- 원문: `10억5600만달러 적자`
- 허용 가능한 구조화 표현: `-1.056 십억 달러`, `-10.56 억 달러`, `-1056000000 달러`
- 파이프라인 표준형: `-1056000000 달러`

## 처리 위치

통화 금액 표준화는 Structured Output 직후, Admission 및 Hard Guard 이전의 결정론적 Claim 복구 단계에서 수행한다. Streamlit·배치·CLI는 모두 같은 `unified_claim_pipeline`과 `admission_recovery_v3`를 사용하므로 한 번의 Core 변경이 세 실행 경로에 동일하게 적용된다.

## 안전 조건

1. 원문에서 통화 금액 표현을 결정론적으로 읽을 수 있어야 한다.
2. Claim의 `value × unit 배율`과 원문 금액이 허용 오차 안에서 정확히 같아야 한다.
3. 통화 기본 단위가 달러로 일치해야 한다.
4. 원문에 `적자` 또는 `흑자`가 있으면 부호와 `condition.polarity`를 함께 정규화한다.
5. 일치하지 않거나 모호하면 기존처럼 HOLD하며 임의로 값을 고치지 않는다.

## 데이터 흐름

```text
OpenAI Structured Output
→ 원문 통화 금액과 배율 비교
→ value를 기본 통화 단위로 환산
→ 적자/흑자 부호 정규화
→ 연간 누계 기간을 기사일 기준 정확한 범위로 복구
→ Admission
→ KOSIS Catalog·Metadata·Hard Guard
→ KOSIS 또는 공식 작성기관 자료 조회
→ Python 판정
```

## 검증

- `-1.056 십억 달러 / YTD`가 `-1056000000 달러 / 2025-01-01~2025-02-20`로 복구되는 실패 회귀 테스트를 먼저 작성한다.
- 같은 금액의 `억 달러`, `십억 달러`, `달러` 표현을 표준화한다.
- 원문과 다른 금액, 다른 통화, 모호한 표현은 표준화하지 않는 음성 테스트를 둔다.
- 대시보드 경계 테스트와 전체 테스트를 통과시킨다.
- 마지막으로 실제 OpenAI Structured Output 및 공식 API 경로를 같은 기사 문장과 기사일로 실행한다.

## 완료 기준

같은 유형의 신규 Claim이 특정 문장별 예외 없이 공식 조회까지 도달하고, 원문과 금액이 일치하지 않는 Claim은 안전하게 HOLD해야 한다.
