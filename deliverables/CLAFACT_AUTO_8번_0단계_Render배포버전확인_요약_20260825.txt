3. 중요한 문제

현재 설정상 배포 브랜치 codex/kosis-gateway는 원격 main보다 117개 커밋 뒤에 있다.
배포 브랜치에만 있는 추가 커밋은 0개이므로 오래된 main의 과거 지점이다.

원격 main:
28c9ec10197dff11a221bb85557b6f2bb4dddac3

현재 통합 실행 브랜치:
3a6b660e56517a60f454e312f2627ce40820e39f

따라서 지금 공개 대시보드가 최신 main 기능이나 이번 KOSIS 구조정보 개선을
사용한다고 볼 수 없다.

4. 왜 체크리스트를 완료로 표시하지 않았는가

설정 화면에는 브랜치 이름만 있고 실제 배포된 Commit SHA는 없다.
공개 Streamlit 상태 응답도 Commit SHA를 제공하지 않는다.
로컬 환경에는 Render API 키와 서비스 ID가 없어 Render 배포 기록을 직접 조회할 수 없다.
GitHub에도 Render deployment 또는 commit status 기록이 없다.

브랜치 최신값과 On Commit 설정을 보면 실제 배포 커밋의 유력 후보는 0530674다.
그러나 과거 커밋 재배포나 수동 롤백 가능성을 공개 정보만으로 배제할 수 없으므로
이를 확정값으로 기록하지 않았다.

체크리스트 완료 기준은 다음 세 값이 직접 확인되는 것이다.

(1) 배포 브랜치
(2) 실제 배포 Commit SHA
(3) 배포 완료시각

현재 (1)은 확인됐고 (3)은 사용자 로그에서 마지막 성공 실행시각을 확인했지만,
(2)가 직접 확인되지 않았다. 따라서 네 번째 체크항목은 보류 상태다.

5. 완료하려면 필요한 한 가지

Render 대시보드에서 해당 서비스의 Deploys 메뉴를 연다.
가장 위의 성공한 배포 항목에 표시되는 다음 정보를 화면으로 공유한다.

- Commit SHA 또는 커밋 링크
- Finished 또는 Live 완료시각

이 한 화면이 확인되면 실제 배포 커밋을 확정하고 네 번째 체크항목을 완료할 수 있다.
